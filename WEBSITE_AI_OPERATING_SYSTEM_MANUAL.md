### 3.1 The 5 Invariant Rules for AI Agents
Whenever you prompt an AI coding assistant, enforce these 5 non-negotiable rules:

1. **Luxury Obsidian & Gold Palette:**
   * Canvas: Deep Obsidian (`#07080a`)
   * Cards / Panels: Charcoal (`#11141c` with `border border-white/10`)
   * Accent: Metallic Gold (`#d4af37` / `hover:bg-[#e5c158]`)
   * Status: Deep Emerald (`#10b981`) and Alert Crimson (`#ef4444`)
   * Typography: High-contrast serif for display headers; crisp sans-serif/mono for UI and data tables.
2. **TypeScript Strict Mode (Zero `any`):**
   * Every component, parameter, and return type must be fully typed.
   * All mutations must use Server Actions (`lib/actions/*.ts`) validated with Zod schemas.
3. **Production Completeness (Zero Stubs):**
   * Never output `// TODO: Implement later` or mock placeholders. All code must be complete, compiled, and ready for production.
4. **Zero-Cost Media Guardrail:**
   * Never store raw video or audio files in PostgreSQL or Supabase Storage. Use embed URLs (YouTube/Vimeo/Stream) and lightweight JSONB for interactive data.
5. **The Verification & Backup Gate:**
   * Before declaring completion, the agent must run `npx tsc --noEmit` to verify type safety and `npm run backup` to snapshot the project.

## 4. Future-Proof Software Architecture & Toolchains

To ensure that *The Architecture of Reality* remains operational, resilient, and immune to software obsolescence for the next 10–20 years, the platform uses a **Durable Headless Stack**.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         FUTURE-PROOF TECH STACK                             │
│                                                                             │
│  ┌───────────────────────┐   ┌───────────────────────┐   ┌────────────────┐ │
│  │      FRONTEND         │   │       BACKEND         │   │   THIRD-PARTY  │ │
│  │ Next.js App Router    │   │ Supabase PostgreSQL   │   │ Resend (Email) │ │
│  │ React Server Comps    │◄──┤ Row Level Security    ├──►│ Cal.com (Calls)│ │
│  │ Tailwind CSS (Luxury) │   │ Edge Server Actions   │   │ Stripe (Pay)   │ │
│  └───────────────────────┘   └───────────────────────┘   └────────────────┘ │
│             │                            │                       │          │
│             ▼                            ▼                       ▼          │
│  ┌────────────────────────────────────────────────────────────────────────┐ │
│  │                VERCEL GLOBAL EDGE INFRASTRUCTURE                       │ │
│  │   Zero-Downtime Deployments · Sub-50ms Worldwide Latency · SSL Auto    │ │
│  └────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 Why This Stack is Future-Proof:
1. **Next.js App Router & Server Components:**
   * Pages are rendered on the server edge, delivering raw static HTML and minimal JavaScript to client browsers.
   * Sub-second load times worldwide with zero client-side bundle bloat.
2. **Supabase PostgreSQL & Row Level Security (RLS):**
   * Open-source PostgreSQL standard. No proprietary vendor lock-in. If Supabase ever changes pricing, the entire database schema (`supabase/schema.sql`) can be migrated to AWS RDS, self-hosted Docker, or Fly.io in under 15 minutes.
3. **Decoupled API Integrations:**
   * **Transactional Email:** Resend (lightweight, zero-bloat REST API).
   * **Calendar Scheduling:** Cal.com (open-source calendar infrastructure; free tier).
   * **Payments:** Stripe Checkout (industry-standard PCI-compliant checkout with local dev bypass).
4. **Git-Backed Content Portability:**
   * All dispatches, books, and blueprints exist as pure Markdown files in the Git repository. If all databases disappear, the content is 100% preserved and readable.

### 4.2 One-Click Automated Backup Protocol
Before performing any structural updates, execute the automated backup script from your terminal:
```bash
npm run backup
```

#### What Happens Automatically:
1. Packages every source file, asset, and database seed into `../Backups/website_backup_YYYY-MM-DD_HHMMSS.zip`.
2. Ignores heavy build artifacts (`node_modules/`, `.next/`).
3. Updates `website_backup_latest.zip` for immediate disaster recovery.
4. Creates a local git tag: `backup-YYYYMMDD-HHMM`.

#### Instant Disaster Recovery (10-Second Restore):
If an experimental change ever corrupts the site, unzip `website_backup_latest.zip` to return the entire codebase to 100% operational status immediately.
